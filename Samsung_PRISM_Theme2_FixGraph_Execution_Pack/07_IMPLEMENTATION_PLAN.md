# Implementation Plan

## Guiding strategy

Build correctness gates first, then retrieval/planning, then caching/performance, then presentation. This prevents a visually impressive prototype from failing hidden contract checks.

## Phase 1 — Foundation and validation

Deliverables:

- repository audit;
- project skeleton;
- exact schema wrapper;
- challenge asset loaders;
- URL-leak validator;
- text/word-count validators;
- deeplink catalog integrity checks.

Exit criteria:

- supplied sample objects can be parsed;
- fabricated deeplink fails;
- web URLs fail;
- invalid title/description/score fails.

## Phase 2 — Deeplink retrieval

Deliverables:

- catalog metadata documents;
- BM25 index;
- dense index;
- hybrid fusion;
- confidence/rejection policy;
- parent-menu traps in tests.

Exit criteria:

- target screen resolution is measurable;
- no code searches by masked URI string;
- every selected URI is a verbatim catalog value.

## Phase 3 — Evidence-grounded plan generation

Deliverables:

- query normalizer;
- symptom atoms;
- evidence segmentation;
- provider abstraction;
- candidate action extractor;
- one-screen grouping;
- risk classifier/sequencer;
- final deterministic compiler.

Exit criteria:

- full cold-path request returns valid schema;
- every action has evidence provenance;
- unsupported evidence produces safe fallback.

## Phase 4 — Semantic cache

Deliverables:

- case signature;
- SQLite cache;
- semantic nearest-neighbor lookup;
- compatibility gates;
- invalidation fingerprints;
- paraphrase benchmark.

Exit criteria:

- no LLM call on valid cache hit;
- held-out hit rate target approached/achieved;
- hard negatives do not generate dangerous false hits.

## Phase 5 — API and resilience

Deliverables:

- `/v1/troubleshoot`;
- `/health`;
- structured logging;
- timeouts;
- safe error boundaries;
- deterministic 50-run regression.

Exit criteria:

- end-to-end API suite green;
- startup/readiness behavior proven.

## Phase 6 — Evaluation

Deliverables:

- supplied sample regressions;
- 100+ adversarial cases;
- screen retrieval benchmark;
- cache benchmark;
- latency benchmark;
- load test;
- ablations;
- red-team report.

Exit criteria:

- every P0 checklist item has evidence;
- reported numbers are generated by committed scripts.

## Phase 7 — Submission

Deliverables:

- Docker;
- README;
- demo harness;
- official PPT completed;
- <=5 minute demo video;
- AI disclosure ledger;
- final contract audit;
- final release tag.

## Time-triage if behind schedule

Never cut:

- schema validation;
- exact catalog integrity;
- URL hygiene;
- evidence grounding;
- safe order;
- basic semantic cache;
- reproducible API.

Cut first if necessary:

- elaborate UI;
- Redis;
- graph database;
- complex dashboard;
- multiple LLM providers;
- excessive animations;
- premature Kubernetes/cloud deployment.
